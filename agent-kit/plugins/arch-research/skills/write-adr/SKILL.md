# Write ADR

1. Знайди KB (як у `research-options`, крок 0) і папку `adr/`. Наступний номер = максимальний існуючий + 1, 4 цифри.
2. Якщо є дослідження в `research/<...>/` — бери контекст, варіанти і ризики звідти, з посиланням. Не переписуй дослідження — посилайся.
3. Заповни `templates/adr.md` → `adr/NNNN-<kebab-title>.md`. Статус — `proposed`, якщо користувач явно не сказав, що рішення прийняте.
4. Якщо рішення замінює попередній ADR: у старому постав `Status: superseded by NNNN`, у новому — `Supersedes: NNNN`.
5. Онови індекс `adr/README.md` (рядок: номер, назва, статус, дата).
6. Розділ "Наслідки" має містити і негативні наслідки. ADR без мінусів — неповний.
7. "Переглянути, коли" — конкретні вимірювані тригери (навантаження > X, вартість > $Y, вихід фічі Z), а не "за потреби".
