# Architecture review

1. Завантаж KB: `constraints.md`, `principles.md`, індекс `adr/` і ADR, релевантні темі.
2. Збери предмет рев'ю: документ, диф (`git diff <base>...`), або опис від користувача. Якщо це код — визнач, які компоненти зачеплені.
3. Перевір по осях:
   - **Відповідність**: порушення constraints / суперечність accepted ADR (з номером ADR).
   - **Надійність**: SPOF, multi-AZ, бекапи, RPO/RTO, поведінка при відмові залежності.
   - **Безпека**: мережеві межі, IAM least privilege, шифрування, секрети, публічна експозиція.
   - **Вартість**: що масштабується лінійно/нелінійно, NAT/data transfer, неочевидні платні фічі.
   - **Експлуатація**: моніторинг, алерти, логи, деплой і відкат, хто on-call.
   - **Еволюція**: lock-in, складність міграції, чи блокує майбутні рішення.
4. Для нетривіальних висновків запусти `devils-advocate` або `option-researcher`, якщо потрібна перевірка фактів.

## Формат
- Вердикт одним рядком: OK / OK з зауваженнями / потребує змін / суперечить ADR NNNN.
- Знахідки: `[BLOCKER|MAJOR|MINOR] вісь — проблема — рекомендація (посилання на ADR/constraint)`.
- Якщо рішення нове і значуще — запропонуй `/arch-research:write-adr`.
